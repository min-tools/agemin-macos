# Build and test

## Public source build

```bash
python3 scripts/build.py
```

The output is `build/Agemin.app`, ad-hoc signed for local use. Source builds keep the 30-day trial, the Free tier's one operation per day, and purchase verification. The access banner stays hidden until startup finishes and appears only after the trial without Agemin Pro. The script does not install or launch the app.

Build options:

- `--configuration Debug`: disable release optimizations and define `DEBUG`.
- `--unsigned`: skip ad-hoc signing.
- `--arch arm64`: select the only supported architecture explicitly.
- `--output /private/tmp/Agemin.app`: choose another output path, ending in `.app`.

The Xcode Debug and Release configurations build the same app:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild -project Agemin.xcodeproj \
  -scheme Agemin -configuration Release \
  -derivedDataPath /private/tmp/AgeminDerivedData \
  CODE_SIGNING_ALLOWED=NO build
```

The script builds in a staging directory and replaces the previous bundle only after all steps succeed.

Swift Package Manager builds (`swift build`) work too. All three build paths use Swift 5 language mode. `Package.swift` defines `AGEMIN_SWIFTPM` so resources and strings load from `Bundle.module`.

## App Store build

Use Xcode's AppStore configuration for App Review. The shared scheme selects it for archives. It defines `AGEMIN_APP_STORE` and includes dSYM crash symbols.

In production, this build counts the trial from Apple's verified original acquisition date. It uses a local trial clock only in verified StoreKit test environments. The Free tier limit, purchase verification, and access banner match the source build.

For compilation and packaging checks, the build script also supports the App Store flag:

```bash
python3 scripts/build.py --app-store
```

This writes `build/app-store/Agemin.app` and leaves the local bundle alone. `python3 scripts/build.py --both` builds both variants at their default paths and does not accept `--output`. Submit only a properly signed Xcode archive, never the ad-hoc bundle produced by the script.

## Source layout

| Path | Contents |
| --- | --- |
| `Agemin.xcodeproj` | The Debug, Release, and AppStore configurations and the shared scheme |
| `Sources/AgeminApp` | SwiftUI interface, the age implementation, key access, and resources |
| `Sources/AgeminApp/Resources/*.lproj` | String catalogs: English plus 30 translations |
| `scripts` | Build script, source export, release audit, icon and screenshot renderers, string catalog sync and translation exchange, the Blowfish table generator, and test suites |
| `docs` | Architecture and build guidance, and the README images |

## Test

```bash
python3 scripts/test_all.py
```

The runner executes every `scripts/test_*.py` suite, two at a time by default (`--jobs`), and writes each suite's log and a `results.json` summary to a fresh directory under `/private/tmp` or to the directory given with `--logs`. A suite that runs longer than five minutes is stopped and counted as failed. Together the suites:

- type-check the source and App Store variants with warnings treated as errors.
- check the age implementation against fixed vectors for scrypt, Salsa20/8, big integers, and the Ed25519 conversion.
- round-trip binary and armored files of several sizes through every recipient type, and detect tampering and truncation.
- parse protected and unprotected SSH keys generated by `ssh-keygen`, along with legacy and unsupported keys.
- when `age` and `age-keygen` are installed, decrypt Agemin's files with `age` and `age`'s files with Agemin.
- test the trial, the daily Free allowance, and the entitlement decisions without StoreKit or an Apple Account.
- drive the purchase panel against a suspended StoreKit stand-in.
- validate localization coverage and format-string safety.
- check that no appearance is forced and that the theme's own colors have Light and Dark variants.
- check the app identity, privacy manifest, entitlements, privacy policy, license, staged packaging, SDK linkage, and the Xcode archive configuration.

No suite launches the app, reads a real key of yours, or makes a purchase. The age suite works in a temporary directory with keys it generates there. Passphrase interoperability with the `age` tool needs `expect` to answer the tool's prompts and is skipped when `expect` is not installed.

After adding or changing text in the source, regenerate the English catalog:

```bash
python3 scripts/sync_english_strings.py
```

Then bring every other language up to date. `scripts/translations.py template <language> <file.json>` writes a JSON file with every English key, prefilled from an existing catalog when one is given with `--reference`. Fill in the translations and import the file with `scripts/translations.py import <language> <file.json>`, which checks the keys and format directives and writes the catalog. The localization suite refuses a language whose core strings are still English.

After changing `scripts/render_icon.swift`, regenerate the bundled icon and its README preview:

```bash
python3 scripts/make_icon.py
```

The README screenshots, `docs/images/hero-light.png` and `hero-dark.png`, are rendered offscreen from the app's own views with fictional keys. Regenerate them when the pictured interface changes:

```bash
python3 scripts/render_hero.py
```

The same run writes the Mac App Store screenshot set, four 2880x1800 scenes over a wallpaper with English headlines, to `private/app-store/screenshots`. Pass `--no-app-store` to skip it.

## Export source

```bash
python3 scripts/export_source.py --output /private/tmp/agemin-source
```

The export copies every file git tracks, plus untracked files git does not ignore, into a new directory. That directory must not exist yet and must be outside the checkout. Repository metadata, build output, app bundles, caches, and Xcode user data are skipped. The export stops with an error if it finds a symbolic link.
