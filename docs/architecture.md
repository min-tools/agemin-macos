# Architecture

Source and App Store builds compile the same Swift files and use the same product identity.

| Concern | Source build | App Store build |
| --- | --- | --- |
| Bundle identifier | `tools.min.agemin` | `tools.min.agemin` |
| Trial clock | Local start date | Apple's verified original acquisition date in production, or a local start date in verified StoreKit test environments |
| Access | 30 days of Pro, then Free or verified Pro access | The same |
| StoreKit verification | Enabled | Enabled |
| Amber access banner | Hidden during startup and the trial, then shown without Pro | The same |
| Build configuration | Debug or Release | AppStore |
| Edition flag | None | `AGEMIN_APP_STORE` |
| Key and file access | User-selected folders and files with security-scoped bookmarks | The same |

## Builds and Pro access

`AGEMIN_APP_STORE` marks App Store builds. A compile-time check refuses an App Store build that also includes the private local override. Debug, Release, Swift Package Manager, and App Store builds share StoreKit verification, the Free tier limit, and the access banner. Swift Package Manager uses `Bundle.module` for resources. Other builds use `Bundle.main`.

`AgeminProStore` verifies purchases, selects the trial clock, and counts the Free tier's daily allowance. The first-launch notice and the initial trial lookup finish before the access banner can appear.

`AppModel` calls the store's `beginOperation()` before each encryption and decryption. After the trial, without Agemin Pro, the store counts the operation. The second operation in a local calendar day opens the Pro panel instead. Viewing keys, reading a file's header, copying, and creating keys are never counted. The count and its day live in preferences. `AgeminFreeAccessPolicy` holds the arithmetic so tests can drive it without StoreKit.

## File access and the sandbox

Agemin runs in the App Sandbox with user-selected file access and app-scoped bookmarks. `KeyStore` keeps bookmarks for the recipients folder, the identities folder, and key files added individually. It opens their security scopes on launch and rescans them on request. The store lists one key line from each `.pub` file in the recipients folder and the private keys it recognizes in the identities folder. It skips SSH configuration files and anything that does not look like a key. It writes a `.pub` file only when the user adds a recipient and deletes one only on request. Agemin writes new age identity files through a save panel.

Users choose input files through an open panel, a drop from Finder, or an Open With request. A drop or Open With request opens its own security scope, which the model closes when the file is replaced or cleared. Results always go through a save panel, so the sandbox grants access to the output path and the user confirms replacing an existing file. Agemin refuses to overwrite the input file with its output.

`FileByteWriter` creates outputs with the POSIX `open` call and mode `0600`, so they are private from the first byte. `AgeEngine` removes the output when a run fails or is canceled. Decryption unwraps the header and verifies its MAC before creating the output file, so a wrong key leaves nothing behind.

## The age implementation

Agemin implements the age v1 format in Swift with CryptoKit and CommonCrypto. It does not bundle or call the `age` binary.

- `AgeFormat.swift` parses and writes the header: the version line, recipient stanzas with their base64 bodies in 64-character lines, and the HMAC-SHA-256 line. `AgePayload` encrypts the body in 64 KiB chunks with ChaCha20-Poly1305 under a counter nonce whose last byte marks the final chunk. HKDF-SHA-256 derives every key.
- `AgeRecipients.swift` wraps the file key for `X25519`, `ssh-ed25519`, `ssh-rsa`, and `scrypt` stanzas. SSH Ed25519 keys are converted to X25519 by `Curve25519Conversion`, with the tweak age defines. RSA uses OAEP with SHA-256 and the age label, implemented in `RSAOAEP.swift` over `BigUInt`, a small arbitrary-precision integer with Knuth division and square-and-multiply exponentiation, using the Chinese remainder theorem when the primes are known.
- `AgeIdentities.swift` unwraps the same stanza types. A passphrase identity refuses work factors above 22, as the age tool does. The engine rejects a header that mixes a passphrase stanza with other stanzas.
- `Scrypt.swift` implements scrypt with Salsa20/8 and PBKDF2-HMAC-SHA-256, checked against the RFC 7914 vectors. `Blowfish.swift` and `BlowfishTables.swift` implement bcrypt's key derivation, which OpenSSH uses for passphrase-protected private keys. The tables contain the hexadecimal digits of pi and are generated by `scripts/blowfish_tables.py`. A key file that asks for more than 4096 bcrypt rounds is refused before any work starts.
- `OpenSSHKey.swift` parses `authorized_keys`-style public keys, the `openssh-key-v1` private key format with AES-CTR and AES-CBC protection, and legacy PEM RSA keys without a passphrase. Other PEM formats are reported as unsupported instead of being read as age identity files.
- `ByteIO.swift` streams files chunk by chunk, so memory use does not grow with the file, and reads and writes the PEM-style ASCII armor. Reading accepts reflowed armor. Writing follows the 64-column layout.
- `AgeEngine.swift` ties these together: inspecting a header, encrypting, and decrypting, with progress and cancellation between chunks.

`scripts/test_age_core.py` checks fixed vectors, generated SSH keys of every supported kind, round trips, tampering and truncation, and, when the `age` tool is installed, decrypts Agemin's files with `age` and `age`'s files with Agemin.

## Interface

Menus use SwiftUI commands because SwiftUI rebuilds menus when focus changes and can drop items inserted through AppKit. Command groups observe the model to keep enabled states and View menu checkmarks current.

`OperationRunner` runs one encryption or decryption at a time on a background task, publishes throttled progress, and carries a cancellation flag the engine checks between chunks. Quitting during a run asks first and cancels it.

The Decrypt page reads a file's header as soon as the file is chosen and marks the identities whose SSH tag matches a stanza. age stanzas carry no tag, so every age identity is a candidate for them. When no key is chosen, the model loads the matching keys first and then every other usable key, and the engine uses the first one that opens the header. Protected keys ask for their passphrase in a modal prompt when they are used.

`AvatarStore` keeps each key's avatar choice in preferences, keyed by the key's fingerprint, or by the age public key for age keys, so a recipient and the matching identity share one avatar. The twelve symbols are drawn in code from their original vector geometry. When the user has not chosen an avatar, its initials use a color derived from the key. An imported image is center-cropped, scaled down to at most 256 pixels per side, and written as PNG into the app container's Application Support folder. Nothing in the key folders changes. The Encrypt page shows recipients as chips with these avatars and marks the user's own keys, found by comparing key material with the identities' public halves.

The window first opens at 1180 by 760 points and cannot shrink below 980 by 600. `WindowFrameMemory` restores the saved window frame and fits it to the screen's visible area without going below the minimum size.

## Localization and appearance

English source strings are localization keys and fallbacks. SwiftUI and AppKit controls share `Localizable.strings` through `localized()`. Agemin ships 30 translations besides English, including Serbian in both scripts, and follows the Mac's language settings. `scripts/sync_english_strings.py` regenerates the English catalog, and `scripts/translations.py` exchanges a language's catalog as JSON. Tests reject missing or stale keys, unsafe format strings, and a language whose core strings are untranslated.

Agemin does not force an appearance. Text, status colors, separators, and accents use AppKit semantic colors. Custom surfaces, inputs, and chips use fixed Light and Dark color pairs resolved through AppKit, and update when the system appearance changes.
